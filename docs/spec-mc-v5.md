# Spec · 《大模型编年史》v5 重塑（固定 2017 开局 + 年龄三档故事线 + 线性十年）

> 日期：2026-08-30 · 执行者：主会话
> 依据：《DSH 工作准则》Spec 驱动；Robin 反馈：「时间线混乱，24 年往后的十年看不到，
> 限定从 2017 年开始，玩家只能选年龄，18 岁过大学四年 / 22 岁从工作开始 / 25 岁面临跳槽。」

## 0. 背景与根因（为什么 v4 时间线是乱的）

v4 是「年份滑杆 2017-2024 × 年龄滑杆 18-25」= 64 组合，靠 §6.0 排期表硬编排每一步的年与年龄。
后果（Robin 线上实测反馈）：开局年份一选，后续年份跳跃（2018 开局次年 2019 就有疫情、D4 在 2021 挂 2024 回声等），
玩家无法在心中建立「一条连续的年线」；2024 之后（2025/2026）体验受开局年份影响大，出现「看不到」的现象。

**结论：取消年份选择，年份固定 2017；年龄三档（18/22/25）各自对应一条人生阶段故事线，
时间线 = 2017 起每年一步，线性走到 2026（十年整），无跳跃、无逆序。**

## 1. 目标

1. 开局页：年份固定 2017（印刷体「2017 年」+ 印章 NO.2017-XX），玩家只选年龄 **18 / 22 / 25**（三张人生卡片）。
2. 三档故事线（生命节点按档位专属，时代节点按年份共享）：
   - **18 岁 · 大学线**：2017 大一入学 → 2018 大二 → 2019 大三（撞上算法/短视频）→ 2020 大四（疫情网课）→ 2021 毕业求职 → 2022 入职 + ChatGPT 发布 → 2023 反诈 → 2024 AI 提效/裁员 → 2025 DeepSeek → 2026 风口/回首 → 结局。
   - **22 岁 · 工作开始线**：2017 应届入职 → 2018 职场第二年 → 2019 算法浪潮 → 2020 疫情居家 → 2021 跳槽窗口 → 2022 ChatGPT → 2023 反诈 → 2024 AI 提效/裁员 → 2025 DeepSeek → 2026 风口/回首 → 结局。
   - **25 岁 · 跳槽/转型线**：2017 工作三年起步（跳槽 or 深耕 or 副业）→ 2018 转型第一年 → 2019 算法浪潮 → 2020 疫情 → 2021 再选择 → 2022 ChatGPT → 2023 反诈 → 2024 提效/裁员 → 2025 DeepSeek → 2026 风口/回首 → 结局。
3. 每局决策数固定 **12 个**（3 档一致）：q1·q2 为档位专属（含 2017/2018/2021 生活线），时代节点 D3/D4b/D4/D5/D6/D7/D8/D9 共享 + 号外 b1/b2 全档必出。
4. 年龄 = 开局年龄 + (年份 - 2017)，结尾年龄：18→27 / 22→31 / 25→34。
5. `策划案-v5.md` 成为唯一权威（v4 作废）；文档↔代码闭环测试改指 v5。
6. 全套测试（lint/logic/ui/visual/doc）+ 平衡模拟（3 档 × 10 结局可达）全绿。
7. 重建 `大模型编年史.zip`；重新部署 GitHub Pages（https://robin-fang611.github.io/llm-chronicle/），验证在线。

## 2. 明确不做（范围外）

- 不改美术风格/CSS 视觉体系（style.css 仅新增「年龄卡片」所需样式，复用既有 token/class 习惯）。
- 不改 10 种结局的准入逻辑与卡面（v4 §8 全部保留，占位符规则只改 {AGE}/{开局那年} 的取值来源——年份固定 2017，公式不变）。
- 不改 16 型人格、21 份档案、中段结算卡、成绩卡的结构（年份字段随新时间线自然变化）。
- 不新增结局/档案/玩法系统；不重写时代节点 D3-D9 的题面（内容本就按真实年份写，正好复用）。
- 不选「年份」，不出现 64 组合；旧存档 `mc_save_v4` 不兼容 → 换 `mc_save_v5`（读旧档直接丢弃，开局页为唯一入口）。

## 3. 时间线模型（v5 权威规则）

**年龄公式**：`step.age = A + (step.year - 2017)`，A ∈ {18,22,25}。

**核心步骤序列（每档相同骨架，共 12 决策 + 中段 + 结局）**：

| 步骤 | 年份 | 节点 | 档位差异 |
|---|---|---|---|
| q1 | 2017 | 起点生活题 | 档位专属题面（18 入学 / 22 入职 / 25 跳槽犹豫） |
| q2 | 2018 | 生活题 | 档位专属题面（18 大二 / 22 职场第二年 / 25 转型第一年） |
| D3 | 2019 | 算法/短视频 | 共享（场景按档位句子微调，2024 版保持一致内容） |
| D4b | 2020 | 疫情 | 共享 |
| q3 | 2021 | 生活题 | 档位专属题面（18 毕业求职 / 22 第五年跳槽窗口 / 25 再选择） |
| b1 | 2022 | 号外 ChatGPT | 共享（全档必出，2022.11） |
| b2 | 2023 | 号外反诈 | 共享（全档必出，2023.5） |
| D4 | 2024 | AI 提效 | 共享，随后中段结算卡（2024） |
| D5 | 2024 | 裁员 | 共享 |
| D6 | 2025 | 人生重算账 | 共享 |
| D7 | 2025 | DeepSeek | 共享 |
| D8 | 2026 | 风口 | 共享 |
| D9 | 2026 | 回首 | 共享，随后结局（2026） |

- 决策数 = 12（q1,q2,D3,D4b,q3,b1,b2,D4,D5,D6,D7,D8,D9 = 12? 数一下：q1, D3, D4b, q3, b1, b2, D4, D5, D6, D7, D8, D9 = 12 项；q2 为第 1 步的「上半场」标记还是独立第 2 步？——**决定：q1(2017) 与 q2(2018) 都是独立决策步，因此合计 13 决策**。见下方严谨序列。）

> 修正（严谨计数）：该序列共 **13 个决策步**（q1、q2、D3、D4b、q3、b1、b2、D4、D5、D6、D7、D8、D9）+ 中段结算（虚拟）+ 结局（虚拟）。
> v4 为 11-12 决策，v5 定 13，每步一年（2024 年两步：D4→中段→D5，中间年数不跳）。

**号外排期（固定，无分支）**：b1 @ 2022.11（ChatGPT），b2 @ 2023.5（反诈）——所有档位每局恰好这 2 次。
b3-b6 数据保留但不进排期（v4 同规则）。

**节点内容年代绑定**（与 v4 完全一致，测试断言）：D3 2019 起 · D4b 2020 · D4 2024 · D5 2024 · D6 2025 · D7 2025 · D8 2026 · D9 2026 · 结局 2026。

## 4. 落地改动清单

### 4.1 content.js
- 删 64 组 `openings/q1/q2`，新增：
  - `startLines[18/22/25]`：三档开局独白（含年龄档标题，如「18 岁 · 大一开始」）
  - `life[year][A]`：三档生活题（2017/2018/2021 三年 × 3 档 = 9 条题面，选项库按档位复用：档位 S1/S2/S3 保留 v4 选项库 q1/q2 的 A/B/C 效果设计，但为档位专属语义重写 label）。
  - `lifeOptLib[band]`：3 条选项库（A/B/C，含 effect/tend/flag/echo/life）。
- 时代节点 D3-D9 与 breaking b1-b6 数据**原样保留**（内容按真实年份写的，正好契合固定 2017 线）。
- `Content.YEARS/AGES` 移除；新增 `Content.START_YEAR=2017`、`Content.AGE_BANDS=[18,22,25]`、`Content.bandForAge(A)`（18-20→S1、21-23→S2、24-25→S3，映射到档位语义：18→大学线、22→工作线、25→跳槽线的选项库）。**三档 = 三条固定年龄，不再 64 组。**
- 结局 `{开局那年}` 占位符 → 恒 2017；`{AGE}` 公式 = A + (2026-2017)。

### 4.2 logic.js
- `buildPlan(A)`：签名只剩年龄（年份恒 2017）；返回 13 决策 + mid + end 的线性序列。
- `modeFor(A)`：18→m3（校园线）、22→m1（职场线）、25→m2（跳槽线）——皮肤跟随档位；`stageForAge(A)`：18→l1、22→l2、25→l3。
- `initialValues(A)`：年份参数隐去，公式按 A 计算（18 岁存款 0.5/技能 15/人脉 20/心态 58；22 更厚；25 最厚、心态最低——为三档差异做初值）。
- `endingParams`：`开局那年` 恒 2017；其余不变；`AGE = A + 9`。
- `stepContent`：q1/q2/q3 走 `life` 表；`era/breaking` 逻辑不变。

### 4.3 ui.js / main.js / state.js / index.html
- `renderOpening`：删除两个滑杆，改为「2017 年 · 你那年几岁」三张卡片（18 岁·大一开始 / 22 岁·工作开始 / 25 岁·转型开始），点卡片 → 更新 stamp/preview/state（整局重建），点「开始」进入。
- `main.js`：`onSlide` → `onPickAge(A)`；`boot()` 默认 18；`onRestart` 保留年龄。
- `state.js`：`SAVE_KEY = 'mc_save_v5'`；`newGame(2017, A)`；`decisionProgress` 不变（q1/q2/q3 加入计数）。
- `index.html` description 改「回到 2017 年，你那年 18/22/25 岁」。

### 4.4 测试
- `test-logic.js`：64 组断言 → 3 档断言；新增「时间线一致性 v5」块（13 步年份序列、年龄公式、号外固定、决策数=13、内容年代绑定）。
- `test-ui.js`：滑杆用例 → 年龄卡片用例（点击 22 岁卡 → stamp NO.2017-22 / preview 联动 / state 重建）。
- `test-doc.js`：解析 `策划案-v5.md` 新表（§3 三档开局 + §6.0 时间线 + §8.4 占位符）。
- `test-visual.js` / `lint.js`：不变（CSS 无系统性变更）；若新增 class 未破坏既有断言则无需改。
- `balance.js`：随机模拟按 3 档 ×13 步重跑；目标导向 10/10 结局全可达；若不可达微调准入并回填策划案。

## 6. 风险与取舍

- **内容工作量**：9 条档位生活题面 + 3 组档位选项库 + 3 条开局独白（约 30 条文案），不复用 64 组旧文案——这是本版改动的核心，功在「故事线清晰」。
- **平衡**：13 步（较 v4 多 1-2 步全档一致），随机分布与可达性用 balance.js 重验；若某结局不可达，优先调准入阈值（回填策划案），不动情节。
- **部署**：GH Pages 仓库公开；push 前勿动旧分支，单次 main push 覆盖即可（同一仓库，历史保留）。
